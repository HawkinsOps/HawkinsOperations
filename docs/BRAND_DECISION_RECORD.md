# Brand Decision Record

Decision date: 03-19-2026

## Canonical naming model

- Public system name: `SignalFoundry`
- Internal implementation name: `AutoSOC engine`
- Portfolio/umbrella identity: `HawkinsOperations` / `HawkinsOps`

## Allowed usage

- Use `SignalFoundry` on public-facing page titles, hero copy, and first-reference system descriptions.
- Use `AutoSOC engine` only when implementation detail matters (runbooks, architecture internals, recovery writeups).
- Use `HawkinsOperations` for repo identity, portfolio framing, and site/company-level navigation labels.

## Disallowed usage

- `AutoSOC pipeline` on homepage, resume, or README summary copy.
- Mixed first-reference naming that introduces `AutoSOC` before `SignalFoundry` on candidate-facing surfaces.
- Unqualified `AutoSOC` mentions in recruiter-speed sections where implementation context is not needed.

## Surface wording requirements

- Homepage: "SignalFoundry" as flagship; proof lane language must differentiate stable benchmark vs runtime snapshot.
- README: introduce `SignalFoundry` first, then clarify `AutoSOC engine` as implementation.
- Resume: project bullets must use `SignalFoundry (AutoSOC engine)` at least once in the top third.
- Proof page: benchmark/runtime labels and source artifact text must remain explicit.
- LinkedIn/post snippets: prefer "SignalFoundry (AutoSOC engine)" on first mention.
